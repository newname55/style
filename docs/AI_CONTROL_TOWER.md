STYLE Webサイト AIコントロールタワー

1. 目的

このドキュメントは、STYLE公式Webサイトの開発・修正・保守をAIが行う際の基準と作業手順を定める。

AIは作業開始前に必ず本ドキュメントを確認し、ここに記載されたルールに従って対応すること。

目的は以下の通り。

* デザイン品質の維持
* スマートフォン表示の品質維持
* 修正による別箇所のレイアウト崩れ防止
* 古い情報の掲載防止
* リンク切れ・404・JavaScriptエラーの早期発見
* AIによる無制限な変更の防止
* 修正前後の状態を確認できる開発工程の確立

⸻

2. 基本方針

STYLE公式サイトではスマートフォン利用者を最優先する。

特に以下を重視する。

* 375px〜430px幅で自然に表示されること
* Hero画像とテキストのバランス
* ナビゲーションの視認性
* CTAの操作性
* 文字の読みやすさ
* セクション間の余白
* 横スクロールが発生しないこと
* 過去イベントなど古い情報が残っていないこと

PC表示だけを基準に修正してはならない。

⸻

3. 作業開始時のルール

コード変更を開始する前に以下を行う。

1. 本AIコントロールタワーを読む
2. 対象ファイルを確認する
3. 変更内容と影響範囲を確認する
4. 関連CSS・JavaScript・HTMLを確認する
5. 必要に応じて現在の表示をPlaywrightで確認する

既存コードを理解せずに全面的な書き換えを行わない。

既存デザイン・構成を可能な限り維持し、必要最小限の変更で対応する。

⸻

4. Playwrightによる表示確認

HTML、CSS、JavaScript、画像、ナビゲーション、レスポンシブ表示など、ユーザーが見る画面に影響する変更を行った場合は、作業完了前にPlaywrightを使用して実際のブラウザ表示を確認する。

標準確認幅

最低限以下を確認する。

* 375px
* 390px
* 430px
* 768px
* 1440px

特に375px・390px・430pxを重要視する。

⸻

5. Playwright確認項目

各画面幅で以下を確認する。

レイアウト

* 横スクロールが発生していない
* 文字が画面外にはみ出していない
* 画像が不自然に切れていない
* セクション間に不自然な余白がない
* 要素同士が重なっていない
* Heroの人物・画像・テキスト位置が自然
* 固定CTAがコンテンツを不自然に隠していない

ナビゲーション

必ずハンバーガーメニューを開いて確認する。

* メニュー背景が十分に不透明
* 背景のHero文字や画像が透けて読みにくくならない
* ナビゲーション文字が正常に読める
* 各リンクがクリックできる
* メニューを閉じられる
* メニュー表示時に不自然な重なりがない

コンテンツ

以下の主要セクションを確認する。

* HERO
* EVENT
* RECRUIT
* CONCEPT
* SYSTEM
* TODAY’S SCHEDULE
* STORE INTERIOR
* ACCESS
* Google Map
* Footer
* 固定CTA

⸻

6. コンテンツ鮮度チェック

表示確認時にはレイアウトだけでなく掲載内容の日付も確認する。

特に以下を確認する。

* 終了済みイベントが掲載されていないか
* 過去の日付が「開催予定」として残っていないか
* 店休日や営業案内が古くないか
* TODAY’S SCHEDULEなど日付依存情報が正常か

終了したイベントを発見した場合は報告する。

AIの判断だけで削除してよいか不明な場合は、勝手に削除せず報告する。

⸻

7. ブラウザエラー確認

Playwright確認時には可能な範囲でブラウザコンソールも確認する。

以下を検出する。

* JavaScript Error
* JavaScript Warning
* 404
* 画像読み込みエラー
* CSS読み込みエラー
* API通信エラー
* faviconエラー
* 外部サービス読み込みエラー

エラーが存在する場合は重要度を分類して報告する。

⸻

8. 問題の重要度

発見した問題は以下の基準で分類する。

Critical

サイト利用そのものに重大な問題がある。

例：

* ページが表示されない
* JavaScriptエラーで主要機能が動かない
* CTAが機能しない
* ナビゲーション不能

High

ユーザー体験に明確な悪影響がある。

例：

* メニュー文字が背景と重なり読めない
* Heroが大きく崩れる
* 文字が画面外にはみ出す
* 横スクロールが発生する
* 重要リンクが404

Medium

利用可能だが改善すべき問題。

例：

* 不自然な余白
* 一部画面幅で画像位置が不自然
* 文言が分かりにくい
* 終了済みイベントが残っている

Low

ユーザー影響が小さい問題。

例：

* favicon.ico 404
* 軽微なconsole warning

⸻

9. 修正後の再確認

問題を修正した場合、コード変更だけで完了としてはならない。

必ず以下を行う。

変更
↓
Playwright確認
↓
問題発見
↓
修正
↓
Playwright再確認
↓
問題なし
↓
完了報告

修正した画面幅だけではなく、少なくとも主要画面幅で回帰確認する。

⸻

10. AIによる変更範囲

AIは依頼された内容を中心に修正する。

以下は禁止する。

* 指示されていない大規模なデザイン変更
* 不要なHTML構造の全面変更
* 必要のないCSSリファクタリング
* 動作しているJavaScriptの無関係な変更
* 理由のないライブラリ追加
* ユーザー確認なしの本番公開

別の問題を発見した場合は、原則として勝手に修正せず報告する。

ただし、依頼された修正によって発生した問題については責任を持って修正する。

⸻

11. 作業完了報告

作業終了時は以下を報告する。

変更内容

どのファイルの何を変更したか。

理由

なぜその変更が必要だったか。

Playwright確認結果

確認した画面幅を記載する。

例：

* 375px OK
* 390px OK
* 430px OK
* 768px OK
* 1440px OK

確認項目

* Hero
* ナビゲーション
* 横スクロール
* 文字はみ出し
* 画像
* CTA
* Console Error

残課題

修正していない問題や判断が必要な内容があれば記載する。

⸻

12. 2026年8月20日時点の基準状態

要確認

ハンバーガーメニュー

文章として不自然に読める可能性がある。

優先度：Medium

優先度：Medium

イベント終了後の掲載ルールを今後検討する。

favicon.ico

favicon.icoへのアクセスで404が確認されている。

優先度：Low

14. AIへの標準指示

STYLEサイトの変更依頼を受けたAIは、

「AIコントロールタワーに従って対応する」

という指示があった場合、本ドキュメント全体を適用する。

コード変更後は、必要なPlaywright確認を自動的に実施し、問題があれば修正または報告する。

作業完了はコードを書いた時点ではなく、表示確認と結果報告まで完了した時点とする。
